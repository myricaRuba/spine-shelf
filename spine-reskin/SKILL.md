# Spine 3.8.75 原骨架换肤

改变原附件的造型，继续使用原骨骼、插槽、约束和动画。仅针对 Spine 3.8.75，不做版本迁移。不把历史项目路径、角色名称、配色或输出页数当作默认要求。

## 定位资源与目标

- 从本次用户提供的目录或文件中定位 JSON、atlas 及其引用的 PNG。存在多套资源时确认正确配对；不把其他排布的 atlas 配到当前 PNG。
- 默认在新的输出目录制作，保留源资源。所有脚本路径通过参数传入；脚本位于本技能的 `scripts/spine_reskin.py`，不依赖当前工作目录。环境要求 Python 3.10+、Pillow。
- 读取 [脚本使用说明](references/automation.md)，先用 `inspect` 建立 `skin → slot → bone → attachment → region → page` 对应清单，再用 `unpack` 导出部件。
- `unpack --alpha straight|pma` 必须按实际资源/渲染器指定；不能根据图片颜色猜测。导出的部件统一是 straight alpha，manifest 记录源模式、资源路径和哈希。
- 同名 region 可能被不同皮肤和附件共用。修改共享 region 会影响全部引用；用户只改某一皮肤时需要显式复制 region 并调整对应 path，不能直接全局覆盖。自动脚本不处理这种 JSON 改写。

## 重绘规则

使用可用的图像生成/编辑能力，先查看原部件再编辑。部件清单应覆盖用户要求的全部同类附件；不要只根据整个人物截图猜测引用。

- 优先保持原 region 名称、逻辑尺寸、裁剪尺寸、offset、orig 和旋转。普通附件的 `x/y/rotation/scale/width/height` 保持原值。
- 保持关节、端点、内部比例和重叠接缝。不要按可见包围盒盲目拉伸，也不要用放大骨骼或改关节补偿错误构图。
- mesh 保留 UV、顶点、权重、拓扑、deform 和 linked mesh 关系，不能改成刚性 region。新纹理须覆盖原网格需要的图案范围。
- 成组编辑可以制作带编号的网格参考图；记录每格与 region 的对应，按实际生成画布裁切。规则网格不保证生成图对齐，需要检查原部件坐标系。
- 制作参考图、裁切生成图、按关节位置登记部件、检查 mesh 覆盖时，读取 [部件与交付工具](references/parts-and-delivery.md)，使用 `spine_parts.py`。坐标、角色、附件和路径均从本次资源与参数取得，不沿用历史映射。
- 仅改变表面设计且保持轮廓时，可以用 `--keep-alpha` 复用原 alpha；扩展轮廓时不要使用此选项。新增轮廓超出原裁剪区域时，需另行计算裁剪和网格覆盖，自动脚本会拒绝尺寸不匹配，不自动改绑定。
- 原尺寸是默认回填目标。高分辨率生成、Real-ESRGAN 是可选制作步骤，不自动把巨幅结果装入图集。`--resize` 仅是显式缩放，不会自动对齐关节或修复内部比例。
- 新轮廓比旧轮廓窄时，默认保留新素材自己的 alpha；不要用旧 alpha 填出空白黑边。部件内部比例不匹配时，按关节登记整个部件。用户要求整条肢体重绘时，不用单独贴手套代替。
- 手掌、指节、武器端点等重要部位，在任何 `--clip-uv` 前检查覆盖率；超过网格应重新对齐或重绘，不能靠最终 mask 隐藏截断。网格覆盖检查只证明采样范围，不证明动作或视觉正确。

## 装回与可选超分

- 按 `replacements.json` 显式选择要替换的 region 和文件；不把所有解包图当作已编辑结果。使用 `replace` 保留原 atlas 布局及 JSON 字节；替换源矩形，不叠加旧像素。
- 需要合并页面或重新排布时使用 `repack`，保留 region 的旋转和裁剪元数据，更新页面和 xy。默认保留全部 region；只有明确确认图集属于这一份 JSON 时才用 `--prune-unused`，避免删除其他骨架共享区域。
- 单页或多页按本次用户要求决定。`repack` 是带边缘扩展的 shelf 单页打包，不保证最优面积或原页面尺寸。
- 用户要求 Real-ESRGAN 时使用 `upscale`，显式提供可执行文件和模型目录；不存在时定位工具或说明缺失，不声称已经运行。该命令接收 straight-alpha PNG，RGB 超分、alpha 单独重采样，再合成。尺寸错误、非零退出或异常全黑输出会终止。
- PMA 在解包时解除、回填时执行一次；原页面中未修改区域不做颜色转换。像素拷贝不传 alpha mask。PNG 使用无损保存，检查半透明边缘和实际尺寸。

## 交付

运行 `validate` 检查 JSON 版本、附件引用、linked mesh 父附件、页面尺寸和区域边界；用 `--baseline-json` 验证 JSON 字节不变，重打包后用 `--baseline-atlas` 验证 region 几何元数据保持一致。这是资源静态校验，不冒充运行时或视觉验证。

按本次任务约定查看组装效果，说明修改范围、输出位置及实际执行的检查。动作验证可由用户完成；用户已经验证的动作无需重复要求。没有示例项目不妨碍执行本技能，不要求额外提供测试工程。

- `spine_preview.py` 只提供静态 setup 组装图，可读取新纹理并处理普通附件、网格与 linked mesh。它不采样动画、不求解 IK/约束，不包含 walk 预览；查看其报告中的省略和近似项。
- 使用 `spine_delivery.py verify` 检查资源和 JSON 语义差异；默认不接受 JSON 变化。用户明确要求结构或动作调整时，仅允许本次指定的 JSON Pointer 路径，列出实际变化，不把动画曲线调整作为换皮默认步骤。
- 用户要求改名写回时，使用 `spine_delivery.py rename` 同步 JSON、atlas、PNG 文件名及页面引用。默认新建目标目录。已获授权更新现有结果时，显式使用 `--overwrite --backup`，保留源角色及旧结果备份；不因脚本可写就推断用户授权覆盖。

不默认新增装饰 slot，不默认固定配色或角色形态。用户明确要求改变结构时按请求处理，并说明哪些绑定或 JSON 字段发生变化。
