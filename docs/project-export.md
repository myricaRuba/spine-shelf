# 游戏项目与通用素材包

v1.4.0 支持将资源库素材组织成游戏项目。项目保存在本机资源库索引中；多项目共享同一份素材文件，每个项目独立保存分类、名称、用途备注和所选皮肤。

## 整理项目

1. 左侧「游戏项目 → +」创建项目。
2. 在项目中「导入资源」选择本地文件夹或 JSON / SKEL，导入后自动加入当前项目；也可「添加素材」挑选资源库已有条目，或在资源库勾选多份素材后「加入项目」。重复加入会保留已有设置。
3. 点击项目卡片底部的分类和皮肤，设置此素材的项目用途和默认显示皮肤。这里选择的皮肤也用于项目内预览。
4. 分类栏可筛选并显示数量。「项目设置」可修改项目名称、备注和分类；分类中存在素材时，需先移动素材再删除分类。「其他」分类保留用于未归类素材。
5. 「导出项目」先选「全部导出」或「按需导出」，再选择目标 Spine 版本，查看素材的处理方式，点击「选择位置并导出」生成 ZIP。成功后在文件管理器中定位，导出时显示转换、整理和压缩进度。

## 导入本地素材

项目页支持拖入本地素材和 Ctrl / ⌘ + O 导入。「添加素材」弹窗也提供「从本地导入新资源」。导入先保存到共享资源库，再按内容分类加入打开导入窗口时的目标项目；同一份素材不会在资源库或项目里重复创建，已有的项目分类、名称、皮肤和备注保持不变。结果分别显示新增入库、复用素材、加入项目和已在项目中的数量，失败的文件单独列出。若素材保存成功但加入项目失败，可重新导入复用这些素材。

## 选择导出素材

默认「全部导出」包含当前项目的全部素材。「按需导出」可逐项勾选，也可按素材名称或分类搜索，使用「全选」「全选搜索结果」和「清空选择」。搜索仅过滤列表，不改变已勾选项；在两个范围之间切换会保留本次弹窗内的勾选。

界面显示本次导出数量和分类数量；未选素材不参与版本检查、转换或打包。ZIP、资源清单、素材条目和进度数量均以本次选择为准，空分类在项目清单中计数为 0。至少勾选一份才能按需导出，操作不改变项目成员或资源库。

## 选择导出版本

- **保留各素材原版本**：保留版本号。JSON 合并皮肤不需要安装 Spine；SKEL 合并新增皮肤时需编辑器先转为相同版本 JSON。
- **Spine 3.8 / 4.0 / 4.1 / 4.2 / 4.3**：向新版本转换时调用本机 Spine 编辑器，转换结果统一为 JSON。3.8.75 选择 3.8 时通过 Spine 3.8.99 重新导出，不修改原文件中的版本字符串。
- **高版本降到低版本**：当前阻止自动导出，逐行说明原因。旧版本无法表达的新约束或动画曲线可能丢失，不把降级当作无损转换。

首次转换时点击「选择 Spine 程序」。Windows 选择 `Spine.exe` 时会自动使用同目录的 `Spine.com`；可手动选择 `Spine.com`。程序路径保存在应用用户目录的 `spine-converter.json`。也支持环境变量 `SPINE_SHELF_SPINE` 和常见安装位置检测。

本机 Spine 必须能正常导出，并能加载源版本与目标版本；找到程序不代表所有编辑器版本已经就绪。转换遵循 [Spine 官方命令行流程](https://esotericsoftware.com/spine-versioning#File-storage)：在临时目录中用源文件对应的完整版本导入 JSON/SKEL 为 `.spine`，再用目标版本导出 JSON。目标 3.8 使用 3.8.99，其他目标使用对应主次版本的最新补丁；例如源 3.8.75 先由 3.8.75 导入工程，再由 3.8.99 导出。

转换后验证实际版本、动画名、原生皮肤、骨骼/插槽数量，并通过目标运行库加载原图集和转换后的骨骼，采样动画骨骼及网格顶点检查非有限值。此检查不等于逐帧视觉一致保证，重要角色仍应在游戏中检查动作。任何转换、加载或校验失败都会停止整包导出，保留原素材和已有 ZIP。

内置分类为人物、地形、道具、特效、界面、其他。自动分配将资源库人物映射为人物、场景映射为地形、普通素材映射为道具、待分类映射为其他；可以手动调整或添加怪物、建筑等分类。项目分类不改变资源库的内容分类。

## 选择皮肤导出方式

默认「可切换皮肤」将原生皮肤及所有 AI 新增皮肤写入同一份骨骼，合并图集并为每套外观保存独立贴图；导入 Cocos 后能在皮肤列表中选择原来的名称。所选项目皮肤保存在 `runtimeSkin` 中，作为游戏里可选的初始外观。

实现遵循 [Spine JSON 皮肤与附件格式](https://esotericsoftware.com/spine-json-format#Skins)：保留原生皮肤，合并基础皮肤和 default 的回退附件，复制网格几何、蒙皮权重及对应变形/序列时间轴。新增图集区域使用独立前缀，附件占位名称、骨骼、约束、绘制顺序和事件保持原语义。基于已有 AI 皮肤制作的新皮肤使用其原生基础骨架及最终贴图。导出前对全部皮肤执行运行库加载和动画采样检查。

「仅当前皮肤」保留原来的单套外观导出方式，体积更小，新增外观固化到贴图中；此模式不会把 AI 外观名称加入骨骼的皮肤列表。未做版本转换时，该模式保留原骨骼字节。

如果 SKEL 有新增皮肤且未连接可用编辑器，会明确阻止可切换导出，不会悄悄改成单套外观。已有原生多皮肤且没有 AI 换肤的 SKEL 可原样导出。

## 包内结构

```text
森林冒险/
  project.json
  资源清单.csv
  使用说明.txt
  SHA256SUMS.txt
  人物-characte/
    主角-<标识>/
      skeleton.json           # 或 skeleton.skel
      skeleton.atlas          # 与骨骼同名，便于引擎自动关联
      page-0.png              # 多页图集会有多个文件，与图集同目录
      skin-1-page-0.png       # 可切换模式下新增皮肤的贴图
      asset.json
  地形-terrain/
    ...
```

名称中的文件系统保留字符会被替换，文件夹附加标识并处理重名。清单内保留原名称。所有文件路径均为相对于清单位置的路径，可整体移动文件夹，不依赖原电脑绝对路径。清单记录空分类，但 ZIP 仅包含有素材的分类文件夹。

`project.json` 包含 `schemaVersion: 1`、项目名称、备注、导出时间、分类和 `assets` 数组。每个素材的 `asset.json` 使用相同字段，文件路径改为相对于该素材文件夹：

| 字段 | 含义 |
| --- | --- |
| `id`, `name`, `note` | 资源标识、项目内名称与用途备注 |
| `categoryId`, `category` | 项目分类标识与显示名 |
| `skin` | 项目中选择的外观名称 |
| `runtimeSkin` | 加载骨骼后应设置的原生 Spine 皮肤名 |
| `bakedSkin` | 是否将 AI 换肤结果固化到了贴图中 |
| `skinMode`, `skins` | 皮肤导出方式，以及骨骼中实际可用的皮肤名列表 |
| `spineVersion`, `runtimeVersion` | 实际导出的 Spine 版本与所需运行库主次版本 |
| `sourceSpineVersion`, `converted` | 转换前版本与此素材是否实际经过版本转换 |
| `format`, `pma` | JSON/SKEL 格式及预乘透明度标记 |
| `animations` | 动画名列表 |
| `skeleton`, `atlas`, `textures` | 骨骼、图集与贴图相对路径 |

`资源清单.csv` 为带 UTF-8 BOM 的表格，包含分类、名称、所选皮肤、运行时皮肤、Spine 版本、动画数量、骨骼路径和图集路径。可能被表格软件解释为公式的文本加前导单引号；JSON 保留原文。`SHA256SUMS.txt` 记录包内其他文件的哈希。

## 在游戏中使用

解压后，将需要的素材文件夹导入游戏工程。将骨骼、`skeleton.atlas` 和 `page-*.png` 一起放入同一目录，按导出清单的 `spineVersion` 选择匹配的 Spine 运行库，并按 `pma` 配置透明度。`project.json` 中的 `targetVersion` 记录用户所选目标；素材的 `spineVersion` 和 `runtimeVersion` 记录实际导出版本。选择保留原版本时可能仍有混合版本，Spine Shelf 内部的 3.8.75 JSON 预览兼容处理不会改变导出骨骼。

Cocos Creator 3.8.8 内置运行库可选 Spine 3.8 或 4.2，没有 4.1 选项；其 3.8 版本检查还明确拒绝 3.8.75。4.1 素材需在匹配目标运行库的 Spine 编辑器中导入并重新导出，3.8.75 素材可重新导出为 3.8.99。修改文件名或版本字符串不等于版本转换。旧导出包若出现「Missing Asset」，需将 `texture.atlas` 改名为 `skeleton.atlas`，或在骨骼资源检查器中手动关联图集；图集每个页名必须对应实际贴图路径。

在可切换模式中，`skin` 与 `runtimeSkin` 相同，`skins` 包含全部原生和新增皮肤。Cocos Creator 组件可调用 `setSkin('丧尸')`，然后调用 `setSlotsToSetupPose()` 重置插槽到设置姿势，再继续播放动画。也可直接在编辑器的皮肤下拉框选择。

在仅当前皮肤模式中，AI 外观的 `runtimeSkin` 指向原生基础皮肤。例如项目外观为「紫发机甲」、基础皮肤为 `default`，游戏中选择 `default` 显示的就是该套机甲贴图。素材包不生成场景、脚本或 Unity/Godot/Cocos 工程。

导出不改变资源库文件；失败时清理临时文件并保留目标位置原有 ZIP。导出包只包含所选素材及项目清单，不包含换肤提示词、任务日志或资源来源目录。

## 验证

- `npm test`：项目持久化、旧库迁移、跨项目独立设置、文件路径与重名、ZIP 内容、哈希、所选贴图、版本判断、转换命令协议、目标运行库校验与失败保护。转换协议测试使用模拟 CLI；本机编辑器能否启动另行实测。
- `npm run test:projects`：真实 Electron 中创建、分类、批量加入、全部/按需导出、解压重导入，检查原版和新增皮肤可以切换、帧像素一致，重启检查持久化。
- `SPINE_TEST_APP` 可指定打包后可执行文件；测试使用独立临时库。
