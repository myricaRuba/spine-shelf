# 游戏项目与通用素材包

v1.4.0 支持将资源库素材组织成游戏项目。项目保存在本机资源库索引中；多项目共享同一份素材文件，每个项目独立保存分类、名称、用途备注和所选皮肤。

## 整理项目

1. 左侧「游戏项目 → +」创建项目。
2. 在项目中「添加素材」，或在资源库勾选多份素材后「加入项目」。重复加入会保留已有设置。
3. 点击项目卡片底部的分类和皮肤，设置此素材的项目用途。这里选择的皮肤也用于项目内预览。
4. 分类栏可筛选并显示数量。「项目设置」可修改项目名称、备注和分类；分类中存在素材时，需先移动素材再删除分类。「其他」分类保留用于未归类素材。
5. 「导出项目 → 选择位置并导出」生成 ZIP，成功后在文件管理器中定位。导出过程中显示正在整理的素材、数量和压缩阶段。

内置分类为人物、地形、道具、特效、界面、其他。自动分配将资源库人物映射为人物、场景映射为地形、普通素材映射为道具、待分类映射为其他；可以手动调整或添加怪物、建筑等分类。项目分类不改变资源库的内容分类。

## 包内结构

```text
森林冒险/
  project.json
  资源清单.csv
  使用说明.txt
  SHA256SUMS.txt
  人物-characte/
    主角-<标识>/
      skeleton.json           # 或 skeleton.skel
      texture.atlas
      textures/
        page-0.png            # 多页图集会有多个文件
      asset.json
  地形-terrain/
    ...
```

名称中的文件系统保留字符会被替换，文件夹附加标识并处理重名。清单内保留原名称。所有文件路径均为相对于清单位置的路径，可整体移动文件夹，不依赖原电脑绝对路径。清单记录空分类，但 ZIP 仅包含有素材的分类文件夹。

`project.json` 包含 `schemaVersion: 1`、项目名称、备注、导出时间、分类和 `assets` 数组。每个素材的 `asset.json` 使用相同字段，文件路径改为相对于该素材文件夹：

| 字段 | 含义 |
| --- | --- |
| `id`, `name`, `note` | 资源标识、项目内名称与用途备注 |
| `categoryId`, `category` | 项目分类标识与显示名 |
| `skin` | 项目中选择的外观名称 |
| `runtimeSkin` | 加载骨骼后应设置的原生 Spine 皮肤名 |
| `bakedSkin` | 是否将 AI 换肤结果固化到了贴图中 |
| `spineVersion`, `runtimeVersion` | 原始 Spine 导出版本与预览运行库主次版本 |
| `format`, `pma` | JSON/SKEL 格式及预乘透明度标记 |
| `animations` | 动画名列表 |
| `skeleton`, `atlas`, `textures` | 骨骼、图集与贴图相对路径 |

`资源清单.csv` 为带 UTF-8 BOM 的表格，包含分类、名称、所选皮肤、运行时皮肤、Spine 版本、动画数量、骨骼路径和图集路径。可能被表格软件解释为公式的文本加前导单引号；JSON 保留原文。`SHA256SUMS.txt` 记录包内其他文件的哈希。

## 在游戏中使用

解压后，将需要的素材文件夹导入游戏工程。保留 `texture.atlas` 与 `textures` 的相对位置，按 `spineVersion` 选择匹配的 Spine 运行库，并按 `pma` 配置透明度。导出不转换骨骼版本；同一项目可包含多个版本，需要分别匹配运行库。Spine Shelf 的 3.8.75 JSON 兼容处理也不会写入导出骨骼。

对于原生皮肤，`skin` 与 `runtimeSkin` 相同。对于 AI 换肤，导出选中外观的图集和贴图，保留原骨骼字节，`runtimeSkin` 指向其原生基础皮肤。例如所选外观是「紫发机甲」，而基础皮肤是 `default`，游戏中加载这份导出贴图后使用 `default` 即可呈现机甲外观。

每份素材在一个项目中选一套外观。本版本不会将所有 AI 皮肤合并进一个骨骼文件，也不生成场景、脚本或 Unity/Godot/Cocos 工程。需要不同外观的素材包时，可在不同项目中选择不同皮肤分别导出。

导出不改变资源库文件；失败时清理临时文件并保留目标位置原有 ZIP。导出包只包含所选素材及项目清单，不包含换肤提示词、任务日志或资源来源目录。

## 验证

- `npm test`：项目持久化、旧库迁移、跨项目独立设置、文件路径与重名、ZIP 内容、哈希、所选贴图、失败保护。
- `npm run test:projects`：真实 Electron 中创建、分类、批量加入、导出、解压重导入，并对比相同动画帧像素，重启检查持久化。
- `SPINE_TEST_APP` 可指定打包后可执行文件；测试使用独立临时库。
